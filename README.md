# memory-game
Разработка программного приложения — компьютерной игры «Память» с системой уровней, подсчётом результатов и сохранением игровой статистики
# Компьютерная игра «Память»

## 1. Подробное описание предметной области

Разрабатываемое программное приложение представляет собой компьютерную игру «Память», предназначенную для тренировки и проверки зрительной памяти, концентрации внимания и способности пользователя запоминать расположение игровых элементов.

Основная идея игры заключается в том, что на игровом поле располагается определённое количество закрытых карточек. Каждая карточка имеет парную карточку с одинаковым изображением. Пользователь поочерёдно открывает карточки и пытается найти одинаковые пары.

Игра содержит систему уровней сложности. При переходе на следующий уровень увеличивается сложность игрового задания за счёт изменения параметров игрового поля и количества карточек.

Приложение автоматически рассчитывает результаты пользователя: количество найденных пар, количество попыток, количество ошибок, затраченное время, набранные очки и достигнутый уровень.

Полученная игровая статистика сохраняется для последующего просмотра и анализа результатов.

### Цель разработки

Целью разработки является создание программного приложения, позволяющего пользователю:

- запускать игру;
- выбирать уровень сложности;
- находить пары карточек;
- получать очки;
- проходить уровни;
- просматривать результаты;
- сохранять игровую статистику.

## 2. Ролевая модель пользователей

В системе выделяются следующие роли:

| Роль | Возможности |

| Игрок | Запуск игры, выбор уровня, прохождение игры, просмотр своей статистики |
| Администратор | Настройка уровней, управление игровыми ресурсами, просмотр общей статистики |
| Разработчик/системный аналитик | Разработка, тестирование и сопровождение приложения |

### Игрок

Игрок является основным пользователем приложения. Он может запускать игровые сессии, выбирать доступные уровни, проходить игру, получать очки и просматривать собственную статистику.

### Администратор

Администратор отвечает за настройку приложения. Он может изменять параметры уровней, управлять игровыми ресурсами и просматривать общую статистику.

### Разработчик/системный аналитик

Разработчик используется систему на этапе разработки, тестирования и сопровождения приложения.


# 3. Функциональные требования

## Модуль игровой сессии

**FR-01. Запуск новой игры.**  
Система должна предоставлять пользователю возможность начать новую игровую сессию.

**FR-02. Выбор уровня.**  
Система должна предоставлять пользователю возможность выбрать доступный уровень сложности.

**FR-03. Завершение игры.**  
Система должна определять статус завершения игровой сессии.

## Модуль игрового поля

**FR-04. Формирование игрового поля.**  
Система должна автоматически формировать игровое поле в соответствии с параметрами выбранного уровня.

**FR-05. Перемешивание карточек.**  
Система должна обеспечивать случайное расположение карточек.

**FR-06. Открытие карточки.**  
Система должна предоставлять пользователю возможность открыть закрытую карточку.

**FR-07. Проверка совпадения.**  
Система должна автоматически проверять совпадение двух открытых карточек.

## Модуль уровней

**FR-08. Уровни сложности.**  
Система должна поддерживать несколько уровней сложности.

**FR-09. Проверка прохождения уровня.**  
Система должна определять успешность прохождения уровня.

**FR-10. Сохранение прогресса.**  
Система должна сохранять информацию о пройденных уровнях.

## Модуль подсчёта результатов

**FR-11. Подсчёт попыток.**  
Система должна автоматически подсчитывать количество попыток.

**FR-12. Подсчёт ошибок.**  
Система должна фиксировать количество ошибок пользователя.

**FR-13. Подсчёт найденных пар.**  
Система должна отображать количество найденных пар.

**FR-14. Расчёт очков.**  
Система должна автоматически рассчитывать итоговое количество очков.

**FR-15. Формирование итогового результата.**  
Система должна формировать итоговый результат после завершения уровня.

## Модуль статистики

**FR-16. Сохранение результатов.**  
Система должна сохранять результаты завершённых игровых сессий.

**FR-17. История игр.**  
Система должна предоставлять возможность просмотра истории игровых сессий.

**FR-18. Лучший результат.**  
Система должна определять лучший результат пользователя для каждого уровня.

**FR-19. Удаление статистики.**  
Система должна предоставлять возможность удаления собственной статистики.

## Административный модуль

**FR-20. Настройка уровней.**  
Администратор должен иметь возможность изменять параметры уровней.

**FR-21. Управление игровыми ресурсами.**  
Администратор должен иметь возможность управлять изображениями карточек.

**FR-22. Общая статистика.**  
Администратор должен иметь возможность просматривать общую статистику приложения.


# 4. Нефункциональные требования

## Performance Efficiency

**NFR-01.** Основные действия игрового интерфейса должны выполняться без заметной задержки.

**NFR-02.** Формирование игрового поля должно выполняться не более чем за 1 секунду при стандартном объёме данных.

**NFR-03.** При одновременной работе нескольких игровых сессий система должна сохранять корректность обработки действий.

## Reliability

**NFR-04.** Система не должна терять сохранённую игровую статистику.

**NFR-05.** При ошибке сохранения система должна уведомлять пользователя.

**NFR-06.** Ошибочное состояние игровой сессии не должно приводить к повреждению статистики.

## Usability

**NFR-07.** Интерфейс игры должен быть понятен пользователю.

**NFR-08.** Состояние карточки должно однозначно отображаться визуально.

**NFR-09.** Уровень, очки, ошибки и попытки должны быть доступны пользователю во время игры.

## Maintainability

**NFR-10.** Основные функции приложения должны быть разделены на отдельные программные компоненты.

**NFR-11.** Добавление нового уровня не должно требовать изменения основной логики игры.

**NFR-12.** Изменение правил начисления очков должно выполняться с минимальным количеством изменений кода.

## Security

**NFR-13.** Доступ к административным функциям должен предоставляться только пользователям с соответствующими правами.

**NFR-14.** Пользователь не должен иметь возможности изменить сохранённый результат через обычный интерфейс.

## Compatibility

**NFR-15.** Приложение должно корректно работать в целевой программно-аппаратной среде.

## Portability

**NFR-16.** Архитектура приложения должна позволять переносить его на другую поддерживаемую платформу.


# 5. Constraints

**Constraint-01.** Первая версия приложения предназначена для одиночной игры.

**Constraint-02.** Игровое поле состоит из парных карточек.

**Constraint-03.** Количество карточек должно быть чётным.

**Constraint-04.** Уровни проходят последовательно.

**Constraint-05.** Статистика сохраняется после корректного завершения игровой сессии.

**Constraint-06.** Основными ролями являются Игрок и Администратор.

**Constraint-07.** Для каждой игровой сессии сохраняются основные показатели: уровень, попытки, ошибки, найденные пары, время, очки и статус.

**Constraint-08.** Сохранённый результат не может быть изменён через пользовательский интерфейс.


# 6. Логическая структура приложения

Приложение состоит из следующих основных модулей:

1. Пользовательский интерфейс.
2. Игровой движок.
3. Модуль управления уровнями.
4. Модуль подсчёта результатов.
5. Модуль статистики.
6. Административный модуль.
